@docs/MODULE-schema-v0.md 의 스키마로 `$ARGUMENTS` 디렉토리의 MODULE.md 초안을 작성해줘.

## 절차 — 반드시 이 순서로, 각 단계 결과를 짧게 보고한 뒤 다음으로

1. 구조 파악: 디렉토리 트리와 각 파일의 public 타입·메서드 시그니처를 나열
2. 진입점 후보: 이 디렉토리 **밖**에서 참조되는 public 심볼만 grep으로 찾아 "호출 위치 → 심볼" 표로 정리
3. 의존 in: 이 디렉토리 코드가 다른 디렉토리의 public 심볼을 실제로 호출하는 곳 (using 선언이 아니라 호출 지점 기준). 엔진·표준 라이브러리는 제외
4. 불변식 단서 수집: 다음을 grep해서 파일:라인과 함께 나열
   - Assert / throw / early return 방어 코드
   - 주석의 "절대", "반드시", "주의", "hack", "TODO"
   - `git log --oneline -30 -- $ARGUMENTS` 에서 fix/버그 커밋
5. 위 근거로 MODULE.md 작성

## 작성 규칙

- **대상 경로에 MODULE.md가 이미 있으면 갱신 모드**: 기존 문장을 유지하고 근거가 바뀐 항목만 고친다. 불변식 ID는 재배열·재사용하지 않는다(폐기는 `- I3. (폐기, 사유) ...`로 남김). 문구 취향으로 다시 쓰지 않는다. 바꾼 항목마다 이력에 한 줄 추가
- 불변식·진입점·의존은 **한 항목에 한 문장**. 두 가지 규칙이 한 줄에 있으면 항목을 나눈다
- 근거의 파일 경로는 **리포 루트 기준**으로 적는다 (`restored-project/Assets/...`). 모듈 상대 경로 금지 — 게이트가 소유 모듈을 찾는 기준
- 이미 상위 MODULE.md 에 있는 불변식과 같은 근거(파일:라인)를 인용하게 되면, 이 모듈에 적고 상위 문서에서는 `(폐기 → [[이 모듈]] I?)` 로 바꾸라고 결과에 명시한다
- 불변식은 참/거짓 판정 가능한 문장만. 각 항목 끝에 `(근거: 파일:라인)` 또는 `(근거: 커밋 해시)`를 붙이고, 검증 방법을 [테스트|grep|리뷰] 중 하나로 표시
- 근거를 못 찾은 규칙은 불변식이 아니라 `미결`에 "불변식 후보:"로 적는다. 추측으로 불변식을 만들지 않는다
- 진입점이 4개 이상이면 3개만 남기고 나머지는 `미결`에 "내부 API 유출 의심:"으로 적는다
- 책임에는 "하지 않는다" 문장을 반드시 하나 포함. 이 디렉토리에 있어도 이상하지 않지만 다른 곳에 있는 기능을 찾아라
- 의존 링크 대상 디렉토리에 MODULE.md가 없으면 `미결`에 "모듈 후보:"로 적는다
- 이력은 `- <오늘 날짜> 최초 작성 (Claude Code 초안, 검토 전)` 한 줄만
- 전체 80줄 이내. 넘으면 줄이지 말고 `미결`에 "분할 후보: <하위 디렉토리>"를 적고 80줄로 자른다
- frontmatter의 `status`는 `draft`로 둔다

## 하지 말 것

- 코드 수정 금지. MODULE.md 파일 하나만 생성
- 스키마에 없는 필드 추가 금지
- 확실하지 않은 것을 확실한 것처럼 쓰지 않는다. 모르면 미결로

## 완료 후

MODULE.md 전문을 보여주고, 마지막에 "사람이 확인해야 할 것" 3개 이내를 따로 적어라. 근거가 약한 불변식, 애매한 경계, 의존 방향이 의심스러운 것 순으로.
