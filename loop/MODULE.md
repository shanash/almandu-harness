## 책임
변경을 게이트 앞이 아니라 **뒤**에 세우는 루프를 소유한다 — 코드를 고치기 전에 그 경로의 소유 계약을 열게 하고(`scope`), 고친 뒤에 기준선과의 차집합으로 "이번 변경이 만든 것" 만 가려내고(`reconcile`), 그 묶음을 커밋한다(`commit`). 게이트가 커밋 시점에만 서 있어 생기는 구멍(DESIGN.md 1절)을 닫는 것이 존재 이유다.
리뷰어를 배치하는 것도 게이트다(`--review`) — 루프는 그 배치대로 테스트와 R13 을 돌려 증거를 모으고(`review`), 기계가 판정할 수 없는 자리에는 판단의 **입력**만 만든다(`review --packet`, DESIGN-review.md 2절).
판정은 담지 않는다 — 규칙도 등급도 게이트가 갖고, 루프는 게이트를 부르고 그 종료 코드를 그대로 넘긴다. 계약서가 사실인지도 판정하지 않는다: `reconcile` 은 되물을 문장을 모아 줄 뿐이고 답은 사람과 에이전트가 계약서에 적는다.
change 단계는 여기 없다. 루프는 고치는 주체가 아니라 고치는 주체를 계약 앞에 세우는 장치다.

## 의존

- 없음. node 표준 라이브러리 넷과 `git` CLI, 그리고 같은 리포의 게이트를 서브프로세스로 부른다 — 조상 모듈과는 링크를 적지 않는다(포함 관계)

## 불변식
- I1. 루프는 계약을 판정하지 않는다 — 게이트를 부르는 명령은 게이트의 종료 코드를, `review` 는 기계 리뷰어(테스트 러너·R13)의 결과를 그대로 낸다. 루프 자신의 거부만 2 다 (근거: loop/loop.mjs:257,272,356,383,409) [테스트]
- I2. 계약을 열지 않은 경로는 커밋되지 않는다 — 묶음의 모든 파일은 가장 깊은 소유 계약이 세션의 적재 목록에 있어야 한다 (근거: loop/loop.mjs:398-403) [테스트]
- I3. 옛 규칙으로 잰 기준선과 새 규칙의 판정으로 차집합을 내지 않는다 — HEAD 가 움직이면 세션을 거부하고, 게이트 소스 해시가 달라지면 HEAD 의 임시 worktree 에서 새 게이트로 기준선을 다시 잰다 (근거: loop/loop.mjs:81,103,106-111) [테스트]
- I4. 기준선은 첫 `scope` 것만 쓴다 — 변경 도중 다시 `scope` 해도 새로 재지 않는다. 새로 재면 그 사이에 만든 경고가 "원래 서 있던 것" 이 된다 (근거: loop/loop.mjs:190-192) [테스트]
- I5. 루프는 작업 트리에 파일을 쓰지 않는다 — 쓰는 곳은 `.git/` 안(세션·리뷰 패킷과 재측정용 worktree 등록)과 OS 임시 디렉토리뿐이고, 작업 트리를 바꾸는 것은 `commit` 의 git 호출뿐이다 (근거: loop/loop.mjs:42,44,82-83,205,313) [테스트]
- I6. active 모듈의 계약이 묶음에 있으면 `계약:` 한 줄 없이는 커밋하지 않는다 — R1 이 코드와 계약을 한 묶음에 묶으므로 메시지가 나누지 않으면 계약 갱신이 이력에서 사라진다 (근거: loop/loop.mjs:414-416) [테스트]
- I7. 같은 트리는 같은 패킷 해시를 낸다 — 패킷에는 임시 경로도 시각도 들어가지 않고 키 순서로 흔들리지 않는다. 해시가 흔들리면 리뷰 결과를 패킷에 묶을 수 없다 (근거: loop/loop.mjs:175-178,311) [테스트]
- I8. 계약 섹션 목록의 출처는 게이트 하나다 — `contract_diff` 는 게이트 소스의 `CONTRACT_SECTIONS` 를 읽어서 자르고, 읽지 못하면 패킷을 만들지 않는다. 사본을 두면 게이트가 섹션을 늘릴 때 리뷰가 그 섹션을 조용히 빠뜨린다 (근거: loop/loop.mjs:129-133) [리뷰]

## 미결
- `scope` 는 계약 **목록**을 낼 뿐 그것을 읽었는지는 모른다. 읽음을 강제하려면 루프가 읽는 주체가 되어야 하고(Agent SDK), 지금은 붙일 자리가 없다 — 목록을 내는 것과 읽는 것 사이의 간격이 이 루프가 남긴 유일한 습관 의존이다
- 묶음의 단위가 작업 트리 전체다. `commit` 은 `git add -A` 로 싣고 `scope` 가 미리 경고하지만, 한 트리에서 두 갈래를 동시에 고치는 작업은 이 루프로 쪼갤 수 없다
- fixture 헬퍼가 module-gate.test.mjs 와 겹친다. 공용으로 뽑으면 테스트 진입점이 라이브러리가 되고, 두면 게이트의 fixture 규약이 바뀔 때 둘이 갈라진다. 갈라지는 것을 본 뒤에 정한다

## 이력
- 2026-09-12 5a — `review --packet` 을 더한다 (DESIGN-review.md 2절). 판정도 판단도 하지 않는 세 번째 표면이라 `--scope`·`--review` 와 같은 급이다: 패킷은 페르소나에게 줄 재료일 뿐이고 답은 호출자가 낸다. 세션 봉인을 그대로 상속하고 게이트가 FAIL 이면 만들지 않는다 — 기계가 이미 거부한 것에 판단을 붙이면 리뷰가 게이트의 대체물이 된다. `contract_diff` 는 hunk 를 고르지 않고 **계약 칸만 뽑아 base 판본과 대조한다**: git 은 markdown 의 섹션을 모르므로 hunk 헤더로는 미결·이력을 가릴 수 없다. 그래서 미결·이력만 바뀐 커밋의 계약 diff 는 빈 문자열이다. 새 불변식 둘 — I7(같은 트리는 같은 해시, 5b 의 결과가 이 해시로 패킷에 묶인다)과 I8(계약 섹션 목록의 출처는 게이트 하나). 테스트 일곱을 더했다 (27개)
- 2026-09-12 `review` 를 더한다 (DESIGN.md 6절). 배치는 게이트의 `--review` 가 정하고 루프는 그 배치대로 리뷰어를 돌린다 — `[테스트]` 는 리포의 테스트 명령을 돌려 통과를 증거로 삼고(명령을 모르면 모른다고 말한다), `[grep]` 은 **R13 의 판정을 그대로 쓴다**: 두 번째 카운터를 만들면 게이트와 갈라지고, 갈라진 두 카운터는 어느 쪽이 맞는지 아무도 못 센다. `[리뷰]` 만 판단에 남긴다. 세션을 요구하지 않는다 — 리뷰 범위는 세션이 아니라 diff 가 정하므로 `scope` 없이도 돈다. I1 을 '루프는 **계약을** 판정하지 않는다' 로 좁혔다: `review` 의 종료 코드는 루프의 판정이 아니라 테스트 러너와 R13 의 결과다. 테스트 넷을 더했다 (20개)
- 2026-09-12 게이트가 바뀌어도 세션을 버리지 않는다 — HEAD 의 임시 worktree 에서 새 게이트로 기준선을 다시 잰다. 루프를 처음 실제로 쓴 커밋(게이트에 `--review` 를 내던 것)이 자기 I3 에 막혀서 드러났다: 이 루프의 첫 용도가 게이트를 고치는 커밋인데(DESIGN.md 5절 "첫 소비자는 이 리포다") 그때마다 세션이 거부되면 루프가 쓰이지 못한다. I3 이 지키려던 것은 '세션을 버린다' 가 아니라 '옛 규칙으로 잰 기준선과 새 규칙의 판정으로 차집합을 내지 않는다' 였으므로 문장을 그쪽으로 고쳤다. 재측정은 HEAD 만 보므로 scope 시점에 이미 더러웠던 변경은 신규로 과보고된다 — 과소보고보다 낫다. I5 도 넓혔다: worktree 등록이 `.git/` 안에, 체크아웃이 OS 임시 디렉토리에 생긴다. 테스트 둘을 더했다 (16개)
